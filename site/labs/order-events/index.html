    Model invariants

    What should stay true?

      These checks describe this teaching model. Passing them is not a security audit or an exactly-once delivery guarantee.

      Read the boundary

      Model limits

      In-memory, single process. Refreshing or resetting clears the event ledger, outbox and receiver. State and outbox changes happen in one pure function here; production needs database transactions, durable uniqueness constraints and concurrency control.

      No authenticity check. This demo does not receive webhooks, verify Stripe signatures, store secrets or call a payment API. It validates only a small synthetic schema, order ID, amount and currency.

      A simplified lifecycle. Payments arriving before checkout are held until checkout arrives. Missing events have no timeout or reconciliation job. Refunds, disputes, partial payments and stock changes are outside scope.

      Idempotent effects need receiver support. The synthetic shipment receiver remembers a fulfillment key. A real worker must reuse a stable key with a receiver that enforces it; an outbox alone cannot prevent every duplicate external side effect.
